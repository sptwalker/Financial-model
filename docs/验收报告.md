### 3.2 记录在案的限制（本次决策：接受，不修复）

> 均为 dev/MVP 阶段的刻意取舍，部署（阶段 4）前必须处理；相关事项已列入 §6。

| 限制 | 风险 | 处理时机 |
|---|---|---|
| SECRET_KEY 硬编码默认值（config.py） | 生产环境可伪造 JWT | 部署时必须从环境变量覆盖 |
| dev-login 在 FEISHU_APP_ID 未配置时开放 | 任何访问者可获 admin token | 仅限内网 dev；部署即失效 |
| OAuth 授权无 state 参数 | CSRF 风险（飞书登录跳转） | 阶段 4 上线前补 state 校验 |
| refresh token 走 query 参数 | 日志/代理可能记录 token | 阶段 4 改为 body 或 httpOnly cookie |
| JWT `sub` 为 str 而 users.id 为 Integer | SQLite 宽容可用；PostgreSQL 会 401 | 阶段 4 统一 str（或改 ORM 映射） |
| `_monthlyize_row` 稀疏数据 bug：年度目标折到 12 月而非逐月均摊 | 年度目标输入在 42 期路径上潜在偏差 | 阶段 3 处理（预测工作台改造该行逻辑） |

### 3.3 良性项目（审查提出，复核后确认非缺陷）

- `Dashboard.jsx:59` 的 setState-in-effect 为异步 fetch 的标准模式（见 §4）；
- 权限 gate 只存在于 API 层（UI 未区分角色）为既定设计，非遗漏；
- 引擎数学在完整 42 期路径对账 BUG=0，与 Excel 结果一致。
